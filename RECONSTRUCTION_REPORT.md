# Video-to-3D reconstruction report

Date: 2026-10-10. Pipeline: `signlingo.motion` version 1, implementation 0.1.0.

## Scope and honest status

This is a working browser reconstruction pipeline and visual investigation environment. It does not establish accurate KSL reproduction. No KSL video was supplied in the initially empty repository; the application starts by requesting an upload. There is no built-in signing animation. The unloaded mannequin is a static, explicitly labeled rest pose.

Implemented: real browser video sampling; actual MediaPipe Tasks Vision CPU/WASM inference in a module worker; anatomical hand association; explicit body/hand coordinate handling; constrained two-bone arm IK; a procedural hierarchical humanoid with independent finger joints; adaptive quaternion filtering and interpolation; synchronized video/3D playback; visual diagnostics; strict versioned JSON interchange; optional per-frame wrist edits; automated tests; GitHub Actions/Pages configuration.

Not implemented: learned sign priors; calibrated multiview reconstruction; dense hand/body meshes; collision/contact optimization; face/blendshape reconstruction; signer-specific calibration; a linguistic correctness model; curriculum, accounts, or scoring. The neutral lower body is presentation geometry rather than tracked leg animation.

## Actual models and runtime

The application uses `@mediapipe/tasks-vision@1.1.0`, Pose Landmarker **full float16 revision 1**, and Hand Landmarker **float16 revision 1**, with `runningMode: VIDEO`, one pose and **two hands**. Detection/presence/tracking thresholds are 0.5. Exact URLs are in `src/motion/types.ts`, the README, and every exported clip. The `.task` assets are publicly downloadable from Google Storage; runtime WASM is loaded from the version-pinned npm package on jsDelivr. Neither weights nor video fixtures are committed.

The Tasks calls are synchronous **inside a Web Worker**, keeping the React UI responsive. Processing is sequential and bounded: ≤120 seconds, ≤250 MB input, 15 or 30 requested samples/second, maximum inference image dimension 960 pixels. Each frame is decoded by seeking an off-DOM HTML video element, drawn to a canvas, optionally unmirrored, transferred as an ImageBitmap, and closed after inference. Every detection retains its requested timestamp in milliseconds. Browser seek behavior selects a decoded frame near that time; this is not a demuxer exposing exact PTS for arbitrary variable-frame-rate files. Repeated source frames are possible when sampling above source FPS.

Tasks 1.1.0 exposed an integration issue in testing: its graph runner clears the global WASM `ModuleFactory` after initialization, but repeated module imports are cached. The worker imports the official ES-module loader once and restores its exported factory immediately before creating **each** landmarker. Both real tasks then initialize successfully. The worker, images, decoder URL, and video resources are released after success, failure, or cancellation. Cancellation during initialization rejects the pending initialization promise immediately.

## Coordinate system and registration

1. Mirroring is an input-pixel operation. If the stored video is mirrored, the sampler reflects it before **both** detectors run. Anatomical pose left/right indexes therefore have the same meaning in both modes. The overlay reverses normalized x again for the original displayed pixels. Mirroring is not guessed from camera/device type.
2. Raw pose image landmarks and pose world landmarks remain separate. MediaPipe world coordinates are approximate hip-centered meters. Convert camera axes with `C = diag(1, -1, -1)`, a proper rotation with determinant +1. Normalize about the shoulder midpoint and scale its span to 0.38 m. Place the normalized shoulder midpoint at avatar `(0, 1.30, 0)`. Root translation is deliberately removed; global walking/sway displacement is not preserved.
3. Raw hand world landmarks have their **own hand-centered origin**. They are never directly concatenated with body coordinates. The explicit translation is `avatar_hand_i = avatar_wrist + C × (hand_i - hand_0)`. This registration uses the common estimated camera axes and a wrist anchor; it is not a calibrated camera solve. The hand's reconstructed rig subsequently uses fixed anatomical offsets/lengths rather than treating noisy estimated lengths as ground truth.
4. Palm +Y is wrist→middle MCP. A handedness-dependent radial vector is formed from index and pinky MCPs; a cross product and Gram–Schmidt step produce a right-handed palm frame. Collinear/degenerate palms are rejected. The palm quaternion is expressed relative to the forearm quaternion.
5. Unique hand assignment minimizes image-space wrist distance over both assignments and missing-hand options. Handedness labels are only a weak tie-breaker. Distant, unreliable, or ambiguous crossing associations are withheld. This is not a learned persistent identity tracker: prolonged occlusions/crossings remain a major failure case.

Both coordinate definitions and original detections are serialized. The `LandmarkDetector` interface is the future backend seam; any alternative must convert its joint indexes, units, handedness, timestamps and coordinate conventions to this contract. No DexAvatar/SAM endpoint or fake adapter implementation is advertised as connected.

## Skeletal reconstruction

The renderer uses a real hierarchy of mesh-bearing joint transforms: torso → shoulder → upper arm → forearm → wrist/palm → three joints for each of five digits. There are **38 quaternion joint rotations**, including torso/head and 30 finger joints. Capsules and palm meshes are articulated through parent/child transforms, not floating landmark spheres. Optional skeleton lines/markers visualize the underlying geometry.

- Upper arm length: 0.28 m; forearm: 0.26 m. Two-bone IK clamps reach using the cosine rule and takes the observed elbow as its bend-plane pole. Near straight-arm singularities it retains the previous pole (or an explicit geometric initial fallback). A suspected pole reversal is flagged rather than silently declared correct.
- Elbow flexion is bounded to 5°–150°, preventing hyperextension. The broad shoulder elevation cone is 170° from torso-down; both wrist-target elevation and resulting upper-arm elevation are bounded. Corrected upper-arm orientation carries the lower arm with it to preserve elbow articulation and lengths. This simplified cone is not a complete biomechanical shoulder model.
- Wrist constraints use swing–twist decomposition around forearm +Y, limiting swing to 85° and twist to ±160°. This broad twist also absorbs forearm pronation/supination because there is no independently estimated radius/ulna roll. It is an approximate combined range, not a clinical wrist joint model.
- Finger segment directions are estimated in the palm/parent frames. Non-thumb MCP flexion is −15°–95°; intermediate/distal flexion is 0°–115°. MCP spread is ±25°, other spread ±5°. Thumb flexion is −25°–95° at its base and −25°–115° downstream, with ±75° base spread. Each thumb has three joints. Axial finger twist is excluded. The thumb base is only an approximate opposition model.
- Every significant clamp stores a joint, correction kind, and magnitude (radians or meters named explicitly). Flagged corrections may change a meaningful sign; they are exposed for inspection. There is no body/hand collision solver; a wrist behind the torso gets a warning, not an automatic assertion that it is wrong.
- Adaptive quaternion filtering uses a 7 Hz body / 10 Hz finger baseline cutoff plus angular-speed dependence. Fast changes are smoothed less. Filtering can still erase very short details; 30 Hz sampling and close video inspection are recommended. Playback uses SLERP only across reliable adjacent observations and gaps ≤200 ms.

## Missing detections and confidence

Pose visibility/presence is gated at 0.45 during reconstruction. A tracked hand requires a valid 21-point set, a classified-hand score ≥0.5, a valid wrist association, and a nondegenerate palm basis. Raw hand handedness scores are **not** calibrated 3D or landmark confidence. The UI labels its conservative minimum-of-arm-visibility/hand-classification value as a **confidence proxy** and never displays an accuracy percentage.

When a hand is lost, its last handshape can be held for at most 200 ms, with state `held`, zero confidence, amber appearance and a warning. After the hold it is hidden. Reliable arm geometry may still be shown. Missing arms are hidden. Missing torso detection withholds tracked reconstruction; if no frame has a reliable torso, processing fails visibly rather than generating an animation.

Warnings identify absent/unreliable hands and arms, ambiguous identity, degenerate geometry, uncertain head orientation, pole flips, image-space wrist jumps, behind-torso depth and constraint corrections. The UI links flags to the timeline. These heuristics are not a completeness guarantee: wrong reconstructions can pass all flags.

## Synchronization, interchange and corrections

With source footage attached, **video.currentTime is the single playback clock**. Animation samples it on each animation frame; pause and seek explicitly copy the final video time. Playback speed is applied to the video itself. Imported motion can run on a standalone clock without footage. Tested speeds include 0.5×; UI exposes 0.25×, 0.5× and 1×.

JSON stores schema version, KSL language tag, exact model URLs/runtime version, source metadata and mirrored flag, coordinate definitions, every sampled timestamp, raw image/body-world/hand-world landmarks, hand classifications and assignments, per-side reliability/tracking state, all local joint quaternions, warnings, automatic corrections, and manual wrist edits. The nonmanual namespace explicitly records approximate head estimation, absent face estimation and absent linguistic validation. KSL is treated as an independent signed language, not a gesture encoding of spoken Korean.

Import validates schema, dimensions/duration, finite values, normalized quaternions, required joint names, landmark counts, strictly increasing in-range timestamps and valid edit/assignment references. JSON is capped at 100 MB. Reattaching a source checks filename/size/duration, not a cryptographic fingerprint. Per-frame manual wrist edits are additive local rotations, bounded again at playback and included in export; no original detector data is overwritten.

- TypeScript strict checking and optimized Vite production build pass.
- **22 numerical/data tests** pass: proper coordinate rotation, shoulder normalization, origin-independent hand registration, invalid geometry, unique anatomical assignment despite reversed labels/order, mirroring transformation, ambiguous crossings, confidence gates, fixed bone lengths and bounded elbow angles over a target grid, pole continuity, wrist swing/twist normalization/idempotence, finite articulated output, short loss holds and expiration, missing torso behavior, quaternion interpolation, missing-endpoint interpolation suppression, timestamp lookup, video-master clock logic, manual edits, round trips and malformed imports.
- Chromium browser tests exercise upload-first state, visible WebGL rig, camera/skeleton controls, mobile overflow, motion import, scrub position, saved wrist edits, export contents, play/pause and invalid JSON errors. Test motion is explicitly synthetic and never shipped as a successful reconstructed sign.
- Opt-in browser integration runs actual Pose + Hand Landmarker inference on uploaded MP4 frames. The initial photo-derived pose fixture produced 15/15 body frames and no hand detections; missing hands were correctly withheld. Successful export was revalidated through the production JSON importer. Scrubbing to 0.4 seconds selected the matching sample, 0.5× playback advanced the video clock, and pause matched the displayed timeline within its 1 ms input step.
- A second 2-second photo-derived video from the official MediaPipe `male_full_height_hands.jpg` asset produced **30/30 body, 30/30 left-hand, and 30/30 right-hand tracked frames**. It yielded 60 real detected hand sets and 443 total heuristic corrections, showing why detection coverage must not be confused with reconstruction accuracy. Cancellation during model initialization also passed a browser test. Sources used only as temporary smoke-test fixtures: `https://storage.googleapis.com/mediapipe-assets/pose.jpg` and `https://storage.googleapis.com/mediapipe-assets/male_full_height_hands.jpg`.
- The real-inference test uses exact upstream model files and installed package WASM served locally at their original URLs through Playwright interception to work within the restricted environment. **Predictions are not mocked.** This tests decoder→worker→models→reconstruction→export→playback; it does not establish CDN availability on every user's network. The selected public `.task` downloads succeeded independently in this environment.
- Temporary photo-derived fixtures exercise infrastructure, not natural signing dynamics. They are not KSL footage, do not establish depth/handshape accuracy, and are excluded from Git. No native-camera ground truth, numerical pose error benchmark, expert signer rating, or KSL intelligibility study was performed.
- Runtime dependency audit found no known vulnerabilities at the time of implementation. No private video/model checkpoint was committed.

## Known failures and next steps

1. Validate consented KSL minimal pairs and continuous clips with a qualified signer. Record handshape, orientation, location, path, coordination and timing separately from technical landmark metrics. No current result supports claiming accurate KSL.
2. Add source hash, signer-specific bone calibration, real video PTS extraction, per-frame pixel reprojection, and error traces. Evaluate left/right swaps, jitter, dropouts, contact error and timing against annotated or multiview references.
3. Improve finger/palm tracking under crossing hands, face contact, blur and occlusion; experiment with full-resolution hand crops and separate refinement. The current 960 px cap and fixed proportions can lose linguistically significant detail.
4. Replace broad heuristic constraints with a calibrated anatomical hand/forearm model and contact-aware optimization. Add elbow-pole editing, depth adjustments, per-joint correction tracks and parameter comparisons. Excessive clamping/smoothing can make a wrong sign look plausible.
5. Preserve facial expression, mouthings, eye gaze, eyebrows, head/body posture and other nonmanual information before calling the avatar an instructor. Current head estimation is too coarse for this role.
6. Evaluate DexAvatar first as an optional offline backend on authorized data/hardware; evaluate SAM 3D Body and HaMeR under the same conditions. Add adapters only after licensing/checkpoints/runtime and an actual measured improvement are established.
7. Test Safari/mobile devices, low-memory environments, codec variations, variable frame rates and real CDN failures. CPU inference speed and sustainable clip size depend on the device; no broad real-time claim is made.
