# 「학습하기」 디자인 — 경로·레슨·복습

「학습하기」는 짧은 레슨을 하나의 세로 경로를 따라 하나씩 깨 나가는 학습 앱 구조입니다. 대상은 수어를 처음 배우는 한국어 사용자(청인 성인 초보자)이며, 모바일(390×844)을 기준으로 설계하고 데스크톱에서는 가운데 정렬로 넓힙니다.

듀오링고에서는 **구조와 감각**만 가져왔습니다. 하나의 학습 경로, 3–5분 레슨, 한 화면 한 문제, 하단 고정 버튼과 아래에서 올라오는 피드백 시트, 립(lip)이 있는 두툼한 버튼, 진행 막대, 완료 축하 화면이 그것입니다. 듀오링고의 캐릭터·전용 서체·고유 색상값·로고·문구·효과음은 쓰지 않습니다.

### 마스코트 "새미"

새싹을 머리에 단 둥근 캐릭터(`src/design/Mascot.tsx`, SVG)입니다. 한국수어에서 표정은 의미를 바꾸는 비수지 신호이므로 **표정(눈썹·눈·입)과 몸 전체의 움직임만으로** 감정을 전합니다. 손은 몸에 붙은 단순한 타원이며 움직이거나 손 모양을 만들지 않습니다. 따라서 어떤 상태도 수어를 흉내 내지 않습니다. 상태: `idle`(경로), `cheer`(완료), `encourage`(오답 시트), `thinking`(로딩), `sleep`(준비 중·빈 상태), `oops`(오류). 레슨 문제 화면에는 넣지 않습니다(오답 시트 옆 작은 얼굴은 예외).

## 경로와 노드

- `buildPath(catalog, store, now)`가 단원·노드·상태를 계산합니다. 각 단원의 공개 표현을 2–3개씩 묶어 레슨 노드를 만들고(1개뿐이면 1개), 그 뒤에 단원 복습 노드와 트로피 노드를 둡니다.
- 노드 상태: `locked`, `current`(한 번에 하나), `completed`, `review-due`(완료한 레슨에 기한이 된 표현이 있음), `coming-soon`(공개 표현이 없는 단원, 누를 수 없음). 공개 표현이 없는 단원은 다음 단원을 막지 않습니다.
- **노드 ID는 단원 ID와 묶인 표현의 `progressKey`(id@revision:sha256)로 만듭니다.** 콘텐츠 revision이나 동작 해시가 바뀌면 완료 표시가 자동으로 풀립니다.
- 지그재그 오프셋 `0, 44, 64, 44, 0, -44, -64, -44`px를 반복하고, 홀수 단원은 방향을 뒤집어 마스코트를 빈 쪽에 둡니다.

## 레슨 구성과 판정 원칙

`buildLessonSession`은 8–12단계를 만듭니다. 새 표현마다 ① 소개 → 쉬운 2지선다 ② → (③ → ④ → 4지선다 ②로 점점 어렵게) → ⑤ 카메라 1회 → 쉬운 2지선다 ②로 끝냅니다.

| 유형 | 판정 |
| --- | --- |
| ① 새 표현 소개 (자동 반복 시범 + 한국어 대응 표현 + 움직임 메모) | 없음 |
| ② 보고 뜻 고르기 | 정답/오답 |
| ③ 뜻 보고 수어 고르기 (보기 A/B/C를 누르면 공용 아바타에서 재생) | 정답/오답 |
| ④ 같은 수어일까요? (시범 1 → 시범 2) | 정답/오답 |
| ⑤ 카메라로 따라 하기 (기존 Practice Mode) | **판정 없음** |

- **수용(보고 이해하기)은 판정하고, 표현(카메라)은 판정하지 않습니다.** 카메라 단계에서 돌아오면 sky 색 중립 시트에 "연습 기록을 남겼어요", 관찰된 차이 최대 3줄, "동작 비교는 정답 판정이 아니에요"만 보여 줍니다. 초록/빨강 시트, 점수, %, 정확도는 쓰지 않으며 완료 화면에도 "따라 하기 N회"만 표시합니다. 카메라 결과는 복습 상자에 쓰지 않습니다.
- 보기는 공개된 표현의 `displayName`과 MotionClip만 씁니다. 다른 단원의 공개 표현을 오답 보기로 쓸 수 있지만, 한국어 대응 표현이 겹치거나 같은 원본 항목·gloss를 가진 표현(예: 여러 뜻의 `없다`)은 같은 문제에 함께 내지 않습니다(`src/learn/similarity.ts`). 오답 보기가 하나도 없으면 ②③④를 만들지 않고 ①⑤만 씁니다.
- ⑤는 `cameraSuitability === 'suitable'`인 표현에만 넣습니다. `지금은 카메라를 쓸 수 없어요`를 누르면 이번 세션의 카메라 단계를 모두 빼고 진행 막대 분모도 줄어듭니다.
- 틀린 ②③④는 레슨 끝에 다시 나옵니다. 틀린 순간에는 진행 막대를 채우지 않고, 다시 나온 문제를 맞혀야 채웁니다. 다시 나올 때 보기 순서는 한 칸씩 돌려 정답 위치가 바뀝니다(위치 암기를 막으면서도 재현 가능).
- 아바타 캔버스(WebGL 컨텍스트)는 레슨 전체에서 1개만 마운트하고 단계마다 `pose`만 바꿉니다. 아바타는 허리 위 상반신만 그립니다.
  - 시점은 `정면 / 1인칭 / 손 확대`입니다. 1인칭은 눈 바로 아래에서 자기 손을 내려다보는 시야라 학습자 자신의 손과 좌우가 같습니다. 손 확대는 문제마다 한 번 정한 고정 구도라 재생 중에 카메라가 움직이지 않습니다.
  - `0.5배속`(표현 카드와 같은 버튼)과 `거울 모드`를 둡니다. 거울 모드는 학습 저장소에 기기별로 저장하며 기본은 꺼짐입니다. 켜면 "거울 모드" 배지가 시범 위에 늘 보이고, 1인칭에는 적용하지 않습니다.
  - 설명(`description`)과 움직임 메모는 새 표현·따라 하기 단계에서 시범 바로 아래에 늘 보입니다. 채점 문항(뜻 고르기·수어 고르기·같은지 비교)에서는 답을 미리 알려 주지 않도록 확인한 뒤 피드백 시트에 나옵니다.
  - 시범 포즈는 몸통 고정과 손 채우기를 거친 표시용 포즈입니다(`docs/DISPLAY_PIPELINE.md`). 채운 손은 반투명 주황색과 "추정으로 채운 손 모양" 범례로 구분합니다.
- 키보드: 1–4 보기 선택, Enter 확인/계속, Esc 나가기 확인. 새 단계마다 문제 제목으로, 시트가 열리면 시트 버튼으로 포커스를 옮깁니다.
- 나가기: "지금 나가면 이번 레슨 진행이 저장되지 않아요" / `계속 학습하기`(주) / `나가기`.
- Practice Mode는 지금처럼 셸이 띄우고 `onResultReviewed`/`onReturnToLesson`으로 돌아옵니다. **레슨 세션 상태(큐·완료·첫 시도 기록)는 셸이 들고 있어** 같은 단계로 돌아옵니다. Practice Mode 내부 UI는 바꾸지 않았습니다.
- 효과음은 Web Audio로 만든 짧은 톤(정답·오답·완료)이며 셸·레슨 화면의 `효과음` 버튼으로 끌 수 있고, 지원 기기에선 짧게 진동합니다. 소리는 유일한 신호가 아닙니다.

## 복습(라이트너 상자)

- 상자 1→5, 다음 복습까지 1·2·4·7·14일(`src/learn/review.ts`).
- 세션이 끝나면 표현마다 한 번만 반영합니다. ②③④를 첫 시도에 모두 맞혔으면 한 칸 올리고(기한이 된 경우에만 — 같은 날 레슨을 반복해도 일정이 부풀지 않음), 하나라도 틀렸으면 상자 1로 돌아갑니다. 새로 배운 표현은 상자 1, 다음 날 복습으로 시작합니다.
- 하단 탭 `복습`과 우측 레일은 기한이 된 표현만 씁니다(최대 4개, 6–8문제, ②③④ 위주). 없으면 "지금은 복습할 표현이 없어요 · 다음 복습: 내일".
- **경로의 단원 복습 노드는 기한이 된 표현을 먼저 쓰고, 모자라면 같은 단원에서 상자가 낮은 표현으로 채웁니다.** 레슨을 끝낸 당일에는 기한이 된 표현이 없어 경로가 하루 동안 멈추는 것을 막기 위한 결정입니다. 기한 전 표현은 맞혀도 상자가 오르지 않으므로 일정은 흐트러지지 않습니다.

- 새 정보는 `signlingo.learn.v2`에 저장합니다: `nodes`(완료 시각·횟수), `expressions`(`progressKey`별 상자·기한·횟수), `settings.sound`. 읽을 때 키 형식·타입·범위·개수(노드 1,000 / 표현 2,000)를 검사하고 손상된 항목은 버립니다. localStorage 접근은 모두 try/catch로 감싸 저장소가 막혀도 학습은 계속됩니다.
- 영상·관절 데이터는 어느 기록에도 저장하지 않습니다.

## 개발 전용 데모 모드

공개 표현이 0개인 동안 흐름을 직접 눌러 보기 위한 기능입니다.

```sh
npm run dev
# http://localhost:5173/?demo=1
```

- `Shell.tsx`에서 `import.meta.env.DEV`가 참이고 `?demo=1`일 때만 `src/dev/demoSource.ts`를 **동적 import**합니다. 프로덕션 빌드에서는 이 분기가 제거되어 데모 모듈이 번들에 들어가지 않습니다.
- 데모 카탈로그(`src/dev/demoCatalog.ts`)는 메모리에서 만들며 `tests/practice-fixtures.ts`의 `practiceClip` 옵션을 바꾼 합성 동작 6개를 `데모 동작 A`…`F`로 표시합니다. 뜻은 "실제 한국수어가 아닌 화면 확인용 동작"이고, 화면 위에 `데모 모드 · 실제 수어 아님` 띠가 항상 고정됩니다.
- 데모 동작은 `loadLessonMotion`/`parseLessonMotion`을 거치지 않습니다. 학습 화면은 `ContentSource` 인터페이스(`src/learn/source.ts`)로 데이터를 받고, 실제 manifest 공급자(`publishedSource`)와 데모 공급자를 갈아 끼웁니다. 공개 파이프라인의 합성 동작 거부 규칙과 검사는 그대로입니다.
- 데모 기록은 별도 키(`signlingo.demo.*`)에 저장되어 실제 학습 기록과 섞이지 않습니다. `public/`에는 데모 파일이 없습니다.
- `npm run build`의 마지막 단계 `scripts/check-dist.mjs`가 `dist/`에서 데모 표식(`SIGNLINGO_DEMO_CONTENT` 등)을 찾으면 빌드를 실패시킵니다.
- 브라우저 테스트는 프로덕션 빌드(`vite preview`)로 돌기 때문에 데모를 쓰지 않고, `tests/content-fixtures.ts`의 `approvedCatalogFixture`가 만든 공개 표현 4개짜리 manifest를 `page.route`로 주입합니다.
