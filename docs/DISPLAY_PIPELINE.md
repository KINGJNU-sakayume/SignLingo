# 표시 후처리 파이프라인 (`src/motion/display/`)

3D 시범을 **화면에 보여 주는 방식만** 바꾸는 계층입니다. 저장된 MotionClip, `public/content/assets/`의 공개 자산, 검수 기록과 MotionClip 스키마는 바꾸지 않습니다. 그래서 이 계층을 바꿔도 재검수가 필요하지 않습니다.

[제약 조건 보정](CONSTRAINTS.md)의 **미리보기**도 이 계층의 단계이므로 같은 규칙을 따릅니다. 제약 조건을 실제로 적용한 보정본(MotionClip v2)은 이 계층 밖에서 저장된 프레임을 기준으로 만들며, 새 revision이므로 다시 검수합니다.

```
MotionClip (+ 시간 복원 결과) ──► baseFrames ──► [단계 1] ──► [단계 2] ──► … ──► DisplayClip
   저장값 · 수정 금지              editedPose()     순수 함수     순수 함수             표시용 프레임 + 프레임별 주석
```

## 불변식

- **입력은 읽기만 합니다.** 각 단계는 새 프레임을 만들어 돌려주고 입력 객체를 바꾸지 않습니다. 테스트에서 클립을 깊게 `freeze`해서 확인합니다.
- **표시 전용입니다.** 저장·내보내기, Practice 비교(`compareMotion`, `features`), 검수 진단(`inspection.json`), Motion Lab의 시간 복원 근거 패널은 모두 원래 클립과 원래 `pose.evidence`를 그대로 씁니다.
- **추정은 숨기지 않습니다.** 채워 넣은 손은 `filled`로 주석을 달고, 반투명 주황색으로 그리며, 범례 "추정으로 채운 손 모양"을 함께 보여 줍니다.
- `reconstruct.ts`의 200 ms 손 모양 유지 규칙, 시간 복원 알고리즘과 저장 데이터는 그대로입니다.

## 인터페이스 (`types.ts`)

| 타입 | 내용 |
| --- | --- |
| `DisplayInput` | `{ clip, temporal? }`. 시간 복원 결과는 Motion Lab에서만 넘깁니다. `learner` preset은 단계 0이 직접 계산합니다. |
| `DisplayFrame` | `{ timestamp, segment, pose, annotation }`. `segment`는 `sequenceBoundary()`(장면 전환·150 ms 넘는 검출 공백)에서 바뀌며, 어떤 단계도 segment를 넘어 값을 잇지 않습니다. |
| `DisplayAnnotation` | `hands[side] = { state, fill?, anchors?, hidden?, constraints?, evidence? }`. state는 `observed / interpolated / held / filled / constrained / rest / missing`입니다. `evidence`는 제약 조건이 바꾼 손이 관측된 손이었는지(`observed`) 관측 없이 만든 값인지(`constrained`)입니다. `arms[side] = 'rest'`(추적되지 않아 쉬는 자세로 그린 팔), `torso?`(모드·편차·손목 잔차·팔꿈치 이동), `contact?`(겹침 해소), 이 프레임을 바꾼 단계 id 목록 `stages`가 붙습니다. |
| `DisplayClip` | `{ frames, stages, reports }`. `reports[stageId]`에 단계별 클립 단위 요약이 들어갑니다. |
| `DisplayStage` | `{ id, run(display, input) => DisplayClip }`. 클립 전체를 받습니다(통계와 양방향 필터에 필요). |

- `runDisplayPipeline(input, stages)`는 `baseFrames`에서 시작해 단계를 목록 순서대로 실행합니다. 기준 프레임에는 `editedPose()`(손목 수동 보정 반영)를 씁니다.
- `sampleDisplay(display, t)`는 `samplePose()`와 같은 규칙으로 보간합니다. 200 ms 넘는 간격, 몸통 없는 프레임, segment 경계에서는 보간하지 않습니다. 차이는 `filled`·`constrained` 손도 보간 대상이라는 점입니다. 단계가 없으면 결과가 `samplePose()`와 정확히 같습니다(회귀 테스트).
- `baseFrames`는 보정본(v2)의 프레임 기록을 읽어, 제약 조건이 손 모양을 정했거나 관측 없이 값을 만든 손을 `constrained`로 시작하고 기록의 `evidence`를 주석에 옮깁니다. 기록에 그 손의 `evidence`가 없으면 바뀐 관절 목록에 있어도 바뀌지 않은 손으로 봅니다(개정판 2 보정본에는 JSON 왕복의 부동소수점 끝자리 차이로 왼손 관절이 "바뀐 관절"에 올라간 프레임이 있습니다). 시간 복원 결과를 쓸 때도 그 손은 저장된 보정값을 유지합니다.
- `displayPose(display, i)`는 Practice처럼 프레임 번호로 재생하는 화면에서 씁니다.
- `handFocus(displays)`는 "손 확대" 시점의 고정 구도입니다. 관측된 손목·손끝 위치의 5–95 백분위 상자를 씁니다. 카메라가 매 프레임 손을 따라가면 그 자체가 멀미를 일으키므로, 클립(또는 한 문제의 클립 묶음)마다 한 번만 정합니다.

### 새 단계 추가하기

```ts
const stage: DisplayStage = {
  id: 'my-stage',
  run(display) {
    const frames = display.frames.map(frame => needsFix(frame) ? withPose(frame, fixed(frame.pose), 'my-stage') : frame);
    return { ...display, frames, reports: { ...display.reports, 'my-stage': summary } };
  },
};
runDisplayPipeline({ clip }, [stabilizeTorso(), stage, fillHands()]);
```

`withPose()`가 주석에 단계 id를 남깁니다. 바꾸지 않은 프레임은 같은 객체를 그대로 돌려주면 됩니다. 새 단계에서도 위의 불변식(입력 불변, 표시 전용, 추정 표시)을 지킵니다. 실제 예가 아래 단계 2 `constrain()`입니다.

## 단계 0 · 시간 복원 `temporal-reconstruct` (`learner`만, 파이프라인 0.3.x 클립)

`learner` preset의 첫 단계입니다(`temporal.ts`). 기존 시간 복원(`reconstructTemporal`, `conservative-bidirectional-v1`)을 그대로 실행해 기준 프레임을 다시 만들고, 앞뒤 관측 사이의 짧은 공백(≤150 ms)을 `interpolated` 손으로 메웁니다. 남은 `held`·`missing` 손만 다음 단계의 손 채우기가 추정으로 채웁니다.

- **적용 조건**: 클립의 `pipeline.temporal`이 있음(0.3.x 추출이 기록), `sampleHz ≥ 15`, 프레임 3–1800개. 하나라도 아니면 프레임을 그대로 넘기고 보고서에 `applied: false`와 이유(`not-recorded` / `sample-rate` / `frame-count`)를 남깁니다.
- 공개 코스 1(v1, 0.2.0)에는 `pipeline.temporal`이 없으므로 **검수받은 화면이 그대로** 보입니다. 테스트가 이전 preset과 프레임 단위로 같은지 확인합니다.
- 반드시 첫 단계여야 합니다(다른 단계 뒤에 두면 오류). `attempt` preset, Motion Lab(자체 시간 복원 UI 유지), 저장되는 MotionClip, Practice 비교에는 쓰지 않습니다.
- 보고서 `reports['temporal-reconstruct']`: 적용 여부와 쪽별 상태 개수(관측·보간·유지·없음).

## 단계 1 · 몸통 고정 `torso-stabilize` (멀미 방지)

1. 몸통이 있는 프레임(`quality.body > 0`)에서 torso 회전의 **기하 중앙값**(Weiszfeld)을 구합니다. 각 프레임의 편차를 구하고, 그 90번째 백분위를 변동량으로 씁니다.
2. **학습 화면(`learner`)은 변동량과 관계없이 중앙값 하나로 고정합니다(`fixed`).** 원본의 인사(고개 숙임)나 몸 기울임도 몸통은 따라가지 않고, 머리는 아래 공식대로 자기 회전을 유지하므로 고개만 움직입니다(2026-10-16 검토: "고개가 움직이는 건데 몸통도 움직이는 것이 부자연스럽다"). 다른 preset(`attempt`, Motion Lab)은 기존 규칙을 씁니다: 변동량이 **8° 이하**이면 고정, 더 크면 실제 몸 기울임으로 보고 시간 기반 1차 저역 통과(1 Hz)를 **앞으로 한 번, 뒤로 한 번** 적용합니다(`smoothed`, 위상 지연 없음).
3. root 위치도 같은 방식으로 처리합니다(중앙값, 1 cm 기준). 현재 복원기는 root를 항상 `[0, 1.3, 0]`으로 두므로 실제로는 바뀌지 않습니다.
4. 프레임마다 보정합니다.
   - 머리: `head' = q_s⁻¹ · q_o · head`. 월드 방향이 원래와 같습니다.
   - 팔: 먼저 `upper' = q_s⁻¹ · q_o · upper`를 적용합니다. 이 공식은 팔과 손의 **월드 방향**을 정확히 보존하지만 **위치**는 보존하지 않습니다. 어깨가 root에서 ±0.19 m 떨어져 있어서 torso가 θ만큼 바뀌면 어깨가 `2·0.19·sin(θ/2)`만큼 움직이고 손도 같이 움직이기 때문입니다. 양손은 서로 반대 방향으로 움직이므로, 손이 맞닿는 수어(예: ksl-meet "손이 맞닿아야 함")에서는 접촉이 벌어질 수 있습니다.
   - 그래서 보이는 팔은 **새 어깨에서 원래 손목 위치로** 고정 길이 2관절 IK(`solveArm`)를 다시 풉니다. 원래 팔꿈치를 굽힘 평면의 pole로 씁니다. 원래 손바닥의 월드 방향은 `distributeForearmRoll`로 다시 붙입니다(복원기와 같은 roll 배분이며, 시간 복원의 `bridgePose`와 같은 방식입니다). 손가락은 손바닥 기준 회전이라 그대로 둡니다.
   - 결과적으로 손목 위치, 손바닥 방향과 모든 손가락 끝이 원래 복원값과 같고 팔꿈치만 조금 움직입니다. 고정 팔 길이 때문에 손목에 닿지 못하는 프레임은 잔차를 주석(`wristResidual`)과 보고서에 남깁니다.
   - 팔이 숨겨진 쪽은 공식만 적용합니다. 몸통이 없는 프레임은 같은 segment에서 가장 가까운 안정 torso를 씁니다.

### 공개 코스 1 측정값

`displayFor(clip, 'learner')` 결과입니다. `tests/display-pipeline.test.ts`가 같은 값을 읽기 전용으로 확인합니다.

| 클립 | 변동량(p90) | 모드 | 표시 torso의 최대 편차 | 손목 잔차 최대 | 팔꿈치 이동 최대 | 프레임 간 torso 흔들림 (deg², 전→후) | 채운 손 (왼손 / 오른손: 앞·중간·뒤) |

| ksl-sorry | 18.4° | fixed (2026-10-16 전: smoothed) | 23.4° | 8.6 mm (쉬는 손; 보이는 손 ≤ 5 mm) | 9.9 cm | 6.44 → 0 | 42·12·26 / 29·14·4 |
| ksl-meet | 4.2° | fixed | 7.2° | 0 | 2.4 cm | 1.51 → 0 | 4·5·4 / 0·4·5 (안전장치 전 5·5·5 / 2·4·5) |

- 공식만 썼다면 손이 쪽마다 최대 2.8 / 6.5 / 2.3 cm 움직였을 것입니다.

- 학습 화면에서 몸통을 늘 고정하면서, 18° 변동한 ksl-sorry 개정판 1·3은 고정 팔 길이 때문에 보이는 손목이 한 프레임 최대 약 5 mm, 쉬는 자세로 그리는 손은 최대 약 9 mm 닿지 못합니다(주석 `wristResidual`).

## 흔들림 줄이기 `smooth-motion` (학습 화면, 몸통 고정·제약 조건 미리보기 뒤)

`smoothMotion()`(`smoothMotion.ts`)은 추적에서 생긴 프레임 사이의 떨림을 학습 화면에서만 줄입니다(저장 동작·Practice·검수 진단은 원래 값).

- 손마다, 팔이 보이고 손이 `missing`이 아닌 연속 프레임(같은 segment, 3프레임 이상)에서 월드 손목 위치·팔꿈치·손바닥 방향·손가락 회전에 **One Euro 필터**(Casiez 외, CHI 2012)를 앞으로 한 번, 뒤로 한 번 적용합니다(지연 없음). 움직임이 느릴 때는 차단 주파수가 낮아(1.2 Hz) 멈춘 손의 떨림을 지우고, 빠를 때는 속도에 비례해 높아져(β = 30 Hz/(m/s)) 짧은 두드림을 남깁니다. 머리 회전도 같은 필터를 거칩니다.
- 그 뒤 팔은 (고정된) 어깨에서 필터된 손목으로 고정 길이 IK를 다시 풀고(필터된 팔꿈치를 pole로), 필터된 손바닥을 복원기의 roll 배분으로 붙입니다.
- 코스 1 측정: 멈춘 구간의 프레임 간 손목 이동이 약 40% 줄고(ksl-thanks 재촬영 후보 0.78 → 0.45 cm), ksl-thanks 개정판 4의 두 번 대기는 닿음(≤1.6 cm)과 그 사이 들어올림(9.5 → 8.1 cm)이 남습니다. 손목을 옮긴 거리는 공개 클립에서 최대 4 cm 미만입니다(`reports['smooth-motion']`).
- 양손이 맞닿아 있으면 두 손이 함께 움직이므로 접촉이 유지되고, 남은 겹침은 마지막 손 겹침 해소 단계가 처리합니다.
- `presentation: false`(일괄 처리 보고서의 추적 지표)에서는 빠집니다.

## 단계 2 · 제약 조건 `constraints` (미리보기)

`constrain(set)`(`constraints.ts`)은 [제약 조건 문서](CONSTRAINTS.md)를 표시 프레임에 적용합니다. 순서는 **시간 복원 → 몸통 고정 → 제약 조건 → 흔들림 줄이기 → 손 채우기 → 쉬는 자세 → 손 겹침 해소**이며, `learnerStages(set)`가 이 순서를 만듭니다. 손 채우기 뒤에 두면 오류입니다.

- 해결기는 보정본 내보내기와 같은 순수 함수 `solveConstraints`입니다. 차이는 입력뿐입니다. 미리보기는 몸통 고정 뒤의 표시 프레임에, 보정본은 저장된 프레임에 적용합니다.
- 제약 조건이 손가락을 정한 손, 또는 관측이 없던(held) 손에 값을 만든 경우 그 손은 **`constrained`** 상태가 되고 주석 `constraints`에 조건 id가 붙습니다. 아바타는 파란 손으로 그리고, 범례 **"보정한 손 모양"** 을 보여 줍니다(레슨·표현 카드·Practice 기준 아바타·Motion Lab).
- 보고서 `reports.constraints`: 조건별 프레임 잔차(전·후), 요약, 프레임별 적용 내역.
- `learner` preset 자체에는 이 단계가 없습니다. 보정본은 제약 조건이 이미 저장 프레임에 들어 있으므로 다시 적용하지 않습니다(상대 회전 `wristOffset`이 두 번 들어가는 일을 막습니다).

## 단계 3 · 손 채우기 `hand-fill`

팔이 보이는데 손이 `held` 또는 `missing`인 프레임을 채웁니다(손가락이 없는 시간 보간 프레임은 손가락만 채웁니다).

| 구간 | 채우는 값 | 주석 |
| --- | --- | --- |
| 첫 관측 이전 | 첫 관측 손 모양 | `fill: 'lead'` |
| 마지막 관측 이후 | 마지막 관측 손 모양 | `fill: 'trail'` |
| 중간 공백 | 앞뒤 관측 손 모양을 시간 비율 t로 slerp | `fill: 'gap'`, `anchors` |

- **손 모양**은 손가락 15개의 회전과 **손목의 상대 회전**입니다.
- 상대 회전은 roll을 뺀 아래팔 프레임 기준입니다. 이 프레임은 팔 형상에서 `solveArm`과 같은 방식(`boneQuaternion(아래팔 방향, 위팔×아래팔)`)으로 다시 계산합니다. 채운 뒤에는 `distributeForearmRoll`로 아래팔 roll과 손목에 다시 나눕니다. 따라서 손은 팔의 움직임을 따라가고, 손목 끝 위치는 바뀌지 않습니다.
- 기준(anchor)은 관측된 손입니다(시간 보간 손은 손가락까지 있을 때만 씁니다). `constrained` 손도 기준으로 쓰지만, 안전장치의 관측 비율에는 **관측된 손을 제약 조건이 조정한 경우(`evidence: observed`)만** 넣습니다. 개정판 2 화면에서는 이 구분이 없어 보정본의 관측 비율이 모두 0으로 계산되었고, 손 채우기 대신 숨김이 일어났습니다. segment를 넘지 않고, 팔이 숨겨진 프레임은 채우지 않습니다.
- **`constrained` 손은 채우지도 숨기지도 않습니다.** 화면 밖 손목이나 관측 근거 부족 규칙도 적용하지 않습니다(제약 조건이 정한 값이며, 표시 상태로 구분됩니다).
- `reconstruct.ts`의 200 ms 유지 규칙과 저장된 `held` 상태는 그대로이며, Motion Lab 진단 패널은 원래 상태(예: "임시 유지")를 그대로 보여 줍니다.

### 손 채우기 안전장치

관측 근거가 부족한 손은 채우지 않고 숨깁니다(`fillHands()`의 기본값 `FILL_DEFAULTS`). 비공개 평가에서 거의 화면 밖에 있던 손을 몇 프레임만 관측하고, 나머지 107프레임을 추정으로 채운 사례가 있었기 때문입니다.

1. **손 단위**: 동작 구간(`activeInterval`, Practice의 동작 구간 추정) 안에서 팔이 보이는 프레임 중 기준(관측, 또는 손가락까지 있는 보간) 프레임의 비율을 셉니다. 이 비율이 **0.15**(`minObservedFraction`) 미만이면 그 손은 클립 전체에서 채우지 않습니다.
2. **프레임 단위**: pose 손목이 화면 밖(가장자리 2%)이거나 신뢰도 0.45 미만인 프레임(`wristInImage`)은 채우지 않습니다(`hideOffscreen`).
3. 두 규칙으로 건너뛴 프레임 중 `held`이거나 원래 채워졌을 `missing` 프레임은 `missing`(손 숨김)으로 표시합니다. 주석 `hidden: 'insufficient-evidence' | 'offscreen'`을 남깁니다. 관측·보간 프레임은 바꾸지 않습니다.
4. 보고서 `reports['hand-fill-guard']`: 손마다 구간, 팔이 보이는 프레임 수, 기준 프레임 수, 비율, 충분 여부, 규칙별 숨김 수. `reports['hand-fill']`(앞·중간·뒤)는 그대로입니다.

`fillHands({ minObservedFraction: 0, hideOffscreen: false })`는 안전장치 전과 같은 결과를 냅니다(테스트로 확인). 공개 코스 1에서 바뀐 것은 ksl-meet뿐입니다. 손목이 화면 밖인 2프레임씩이 채움에서 숨김으로 바뀌었습니다.

| 클립 | 손 | 채움 앞·중간·뒤 (전 → 후) | 숨김(화면 밖) | 동작 구간 관측 비율 |
| --- | --- | --- | ---: | ---: |
| ksl-thanks | 왼 / 오 | 38·0·31 → 같음 / 35·8·29 → 같음 | 0 / 0 | 0.425 / 0.400 |
| ksl-sorry | 왼 / 오 | 42·12·26 → 같음 / 29·14·4 → 같음 | 0 / 0 | 0.200 / 0.520 |
| ksl-meet | 왼 / 오 | 5·5·5 → 4·5·4 / 2·4·5 → 0·4·5 | 2 / 2 | 0.819 / 0.843 |

가장 낮은 비율은 ksl-sorry 왼손의 0.200으로, 기준 0.15보다 높아 그대로 채웁니다. `tests/diagnostics.test.ts`가 이 표를 고정합니다.

## 단계 4 · 쉬는 자세 `rest-pose` (수어 앞뒤)

학습 화면에서 수어 앞뒤의 **쉬는 자세**를 보여 주는 표현 단계입니다(`restPose.ts`). 개정판 2 검토에서 나온 세 문제를 다룹니다. 팔이 추적되지 않으면 팔이 사라져 부자연스럽고, 쉬는 손에 수어 손 모양이 들어가 시작·끝이 어색하며, 그 손 모양 때문에 문제를 움직임을 보지 않고 맞힐 수 있었습니다.

- **수어 구간과 쉬는 자리**는 `signingInterval`(`src/motion/signing.ts`)이 정합니다. 손목이 쉬는 자리에서 10 cm 넘게 떨어진 프레임이 "올라간" 프레임입니다. 쉬는 자리는 그 팔이 처음(끝) 보인 세 프레임의 손목 위치(충분히 낮을 때), 아니면 몸 옆 기본 위치이고, 깊이 차이는 절반만 셉니다. 손목이 쉬는 자리에 가까운 정도(4 cm 이하 1, 10 cm 이상 0, ±2프레임 평균)를 쉬는 가중치로 씁니다.
- **쉬는 손**은 손가락을 조금 구부리고 손바닥이 허벅지 쪽, 손끝이 아래팔 방향인 편안한 손입니다. 손이 처음 올라가기 전과 마지막으로 내려온 뒤에는 관측된 손도 쉬는 손으로 그립니다. 수어자가 손을 올리기 전에 손 모양을 미리 만들어 두는 경우가 많고, 그 모양이 첫 화면에 보이면 답을 짐작할 수 있기 때문입니다.
- **쉬는 손 ↔ 수어 손 전환은 시간으로 섞습니다**(개정판 3 검토 소견 "쉬는 자세에서 동작으로의 이동이 자연스러웠으면"). 올라갈 때는 손목이 쉬는 자리를 떠나는 순간(4 cm 이내였던 마지막 프레임)부터 수어 위치에 도착하는 순간(처음 0.7초 안 최대 거리의 85%)까지(최소 250 ms), 편안한 손에서 **도착할 때의 손 모양**으로 바뀝니다. 그 사이 프레임의 손(관측이 없거나 미리 만든 손)은 쓰지 않습니다. 내려올 때는 손 모양을 유지하다가(내리는 동작도 수어일 수 있습니다) 쉬는 자리에 닿기 전 마지막 350 ms 동안 그 프레임의 손에서 편안한 손으로 풀립니다. 이때 따라가는 손 모양은 초당 400°보다 빨리 바뀌지 않아, 제약 조건 구간 끝이나 잡음으로 한 프레임에 손바닥이 50° 꺾이던 것이 사라집니다. 손의 색도 같은 가중치로 회색과 원래 색 사이를 서서히 바꿉니다(`restWeight`, `under`).
- 측정(코스 1 개정판 3, 학습자 표시): 한 프레임 손가락 회전 최대가 고맙다 52°→14°, 만나다 148°→16°입니다(손이 오르내리는 프레임). 미안은 수어 중 나머지 손가락 관측 잡음(최대 137°)을 제약 조건에서 정해 클립 전체 최대 10°입니다.
- 수어 구간 안에서는 관측이 없는 손이 쉬는 자리 가까이로 돌아왔을 때만 거리에 따라 쉬는 손으로 섞습니다(히스테리시스 0.6/0.4).
- **수어에 참여하지 않는 손**(수어 구간에서 올라간 프레임이 15% 미만, 예: 한 손 수어의 반대 손)은 처음부터 끝까지 쉬는 손입니다.
- **추적되지 않은 팔**은 그 팔의 첫 지속 추적(150 ms 이상) 전과 마지막 지속 추적 뒤에 쉬는 자리에 매달린 팔로 그리고(고정 길이 IK, 팔꿈치는 조금 뒤·바깥), 추적된 첫(마지막) 자세와 300 ms에 걸쳐 섞습니다. 수어 중간에 팔을 놓친 구간은 양 끝이 모두 쉬는 자리일 때만 채우고, 손을 든 채 놓친 팔은 그대로 숨깁니다.
- 쉬는 손과 팔은 주석 `rest`(손), `arms[side] = 'rest'`(팔)을 달고 몸통과 같은 회색으로 그립니다. 범례 **"회색 팔·손: 수어 앞뒤의 쉬는 자세"**가 레슨·표현 카드·Practice 기준 아바타에 붙습니다. `quality`와 관측 근거는 그대로라 Motion Lab 진단은 원래 상태를 보여 줍니다.
- 보고서 `reports['rest-pose']`: 쪽마다 쉬는 팔·쉬는 손·섞은 프레임 수와 참여 여부(`passive`).

### 손 채우기의 손바닥 잇기

제약 조건이 손가락만 정하고 손바닥 방향은 정하지 않은(`palmFacing`·`wristOffset`·`symmetry`·`hold`가 없는) 비관측 손은, 복원기의 200 ms 유지 때문에 옛 손바닥 방향에 멈춰 있다가 다음 관측에서 한 번에 넘어갈 수 있습니다(ksl-sorry 개정판 3: 프레임 57–60 유지, 61에서 126°). 손 채우기 단계는 앞뒤 관측이 300 ms 안에 있으면 그 사이 손바닥 방향만 시간 비율로 잇고 손가락은 제약 조건 값을 그대로 둡니다(보고서 `hand-fill`의 `palm`).

| 클립 (공개 개정판 2) | 수어 구간 | 쉬는 손 / 쉬는 팔 (왼 · 오) | 참여하지 않는 손 |
| --- | --- | --- | --- |
| ksl-thanks | 1.27–3.00 s | 손 65 · 65 / 팔 0 · 0 | - |
| ksl-sorry | 1.13–2.63 s | 손 100 · 50 / 팔 1 · 3 | 왼손 |
| ksl-meet | 1.37–3.40 s | 손 12 · 11 / 팔 39 · 41 | - |

수어 구간은 표시하는 클립 자체에서 잽니다. ksl-sorry 개정판 2는 이마 접촉 보정이 손을 미리 끌어올려 1.13 s부터이고, 해결기가 쓰는 원본(개정판 1) 기준은 1.20 s입니다.

## 단계 5 · 손 겹침 해소 `hand-contact`

두 손이 서로 파고들지 않게 합니다(`separateHands.ts`, 기하는 `src/motion/handContact.ts`). 손 부피는 아바타 메시와 같은 크기의 손가락 캡슐(반지름 10/8/7/6 mm), 손바닥 캡슐 3개(13 mm), 손목 구(22 mm)입니다.

- 두 손이 모두 보이는 프레임에서 부피가 겹치면, 겹침 법선들의 깊이 가중 평균 방향으로 양손을 반씩, **표면이 닿는 최소 거리**(0.5 mm 이내)만큼 평행 이동합니다. 손바닥 방향과 손가락은 그대로이고 팔은 고정 길이 IK로 다시 풉니다.
- 개정판 2의 ksl-meet는 맞대기 제약 때문에 두 손목이 같은 점에 놓여 손이 최대 4.1 cm 겹쳤습니다. 이 단계 뒤에는 주먹 쥔 손가락 마디가 맞닿습니다(20프레임, 손마다 최대 4.7 cm 이동, 남은 겹침 0.5 mm 이하). 해결기 v2도 같은 기하로 겹침을 풀기 때문에, 개정판 3 보정본에는 이 단계가 바꿀 겹침이 없습니다.
- 주석 `contact = { before, after, shift }`, 보고서 `reports['hand-contact']`(프레임 수, 최대 겹침 전·후, 최대 이동).

단계 4·5는 **표현 단계**입니다. 추적 근거를 세는 보고서(`motion:batch`·`motion:compare`의 학습자 표시 열)는 `learnerStages(undefined, { presentation: false })`로 이 두 단계를 빼고 셉니다.
